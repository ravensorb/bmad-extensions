# Decision Log

## Session 2026-05-15 — Initial Build

**Classification: Complex Workflow.** Epic planning + sprint execution loop + 8 closure phases would far exceed 250 lines inline. Carved into two references: `sprint-execution-loop.md` and `epic-closure.md`. SKILL.md handles activation and epic planning (Step 1), which is short enough to stay inline.

**Interactive only — no headless mode.** Epic-execute is always user-invoked. Sprint-execute subagents handle headless execution per sprint. Epic orchestrator needs the user present for sprint grouping confirmation, between-sprint check-ins, and closure decisions.

**Functional completeness review added.** Not in sprint-execute; epic-level only. Checks each PRD acceptance criterion against implementation across all stories. Critical gate for epic closure.

**Closure parallel batch architecture.** Retro runs first (sequential) because it's referenced by adversarial and red-team. After retro: clean release + adversarial + red team + UX may run in parallel when outputs are isolated files and no safety check fails. Architecture drift and functional completeness are always sequential (inline analysis that reads multiple files simultaneously).

**Architecture drift scope: full solution.** Unlike sprint-execute's light/sprint-scoped analysis, epic drift looks at the entire implemented solution against the architecture spec. Four-category classification: INTENTIONAL, UNDOCUMENTED, SPEC GAP, MISSING.

**Issue resolution richer than sprint.** Epic adds "doc update" as a resolution option (for spec gaps and intentional drift that needs architecture doc updates), not just fix/defer/accept.

**Sprint grouping at epic planning.** User confirms how remaining stories are split into sprints before execution begins. Defaults to all stories as one sprint; user may provide groupings.

**Config path: `{project-root}/_bmad/config.yaml` (`l3io-pm` section).** Same as sprint-execute.

**Calls l3io-pm-sprint-execute as subagent.** Epic orchestrator spawns one sprint-execute subagent per sprint. Sprint-execute runs headlessly when called this way.
