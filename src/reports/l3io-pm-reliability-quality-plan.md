# Implementation Plan — Six BMad PM Reliability & Quality Fixes

Status: **approved — Phase A in progress**
Scope: `l3io-pm` (both PM skills) + `l3io-arch` module.

## Motivating pain points (from the field)

1. After planning epics/stories, a full arch review is needed to close a lot of gaps/assumptions.
2. Stories don't always have technical acceptance criteria — implementation left to individual agents.
3. The default 2-parallel-agent restriction is useless; better to let the agent decide.
4. Subagents almost always lose token/cost actuals — **not acceptable** (runtime: both Claude and Copilot).
5. Subagents don't always keep the sprint status file up to date — hard to track progress.
6. Subagents don't report progress on a regular basis.

## Design principles

1. **One keystone script.** Pains 5, 6, and the safety precondition for 3 all resolve to a missing primitive: a deterministic, atomic, round-trip-safe status/ledger writer. Build it first.
2. **Disk handoff over transcript archaeology.** For pain 4, each subagent self-reports usage in its DONE line; the transcript glob becomes reconciliation, not the sole source.
3. **Shift the arch review left.** Pains 1 & 2 are the same gap at two altitudes: architecture is only reviewed at closure. Add gates at planning (epic) and story prep using the `l3io-arch` module.
4. **Config-gated, backward-compatible.** Every gate behind a `customize.toml` flag with graceful degradation when an optional dependency is absent (the `l3io-sec-agent-redteam` skip pattern).

## Structural facts (constrain where edits land)

- **`src/` is the authoring source of truth.** `.claude/skills/` and `.agents/skills/` are installed copies regenerated by the BMad installer on reinstall/upgrade. There is no `src→.claude` build script (only `postbump` version sync). All edits land in `src/`.
- **Shared references are byte-identical duplicates** across both PM skills (`metrics-contract.md`, `status-files.md` have matching md5s). Every contract edit must be mirrored to both copies. Recommend a CI md5-parity check to catch drift. The new `scripts/pm-status.py` is duplicated the same way.

## Phase A — Foundation: `pm-status.py` (pains 5 & 6, unblocks 3)

Canonical source: `src/l3io-pm/_shared/pm-status.py` (+ `_shared/tests/`) — authored **once**. `npm run sync:scripts` (chained into `postbump`) generates the per-skill `scripts/` payload copies; `npm run check:scripts` (CI) fails on drift. At module setup each PM skill runs `pm-status.py self-install --dest {project-root}/_bmad/scripts/pm-status.py` (version-guarded, self-healing on first use), so there is one runtime copy per project, referenced by both skills as `{project-root}/_bmad/scripts/pm-status.py` — the shared-runtime-utility pattern (`resolve_customization.py`), **not** the per-skill `merge-config.py` bootstrap pattern. (Original plan placed a hand-mirrored copy in each skill's `scripts/`; refactored to this shared model to remove authoring + runtime drift.)

Runtime: `uv run` + PEP-723 inline deps pulling **`ruamel.yaml`** (round-trip: preserves key order + comments so diffs stay clean and files stay human-readable). Matches BMad's "standardizing on `uv run`" direction.

Subcommands:

| Command | Purpose | Atomicity |
|---|---|---|
| `set-status --file <status_active> --story KEY --status S` | Locate node across the 3-file split, set `status` + `updated_at`, write back | temp-file + `os.replace` |
| `set-actual --node <story\|sprint\|epic> --key K --tokens-k … --cost … --elapsed-hours … --man-hours …` | Write a validated `actual` block | rejects a missing metric under `--runtime claude` |
| `progress --ledger <path> --msg "…"` | Append `ISO8601  EPIC/SPRINT/STORY  message` to `progress.log` | append-only |
| `verify --scope <sprint\|story> --require-tokens` | Read-back gate; exit ≠ 0 on any absent/N-A-under-claude field | — |

Wiring (both PM skills):
- Replace every prose status transition with a `pm-status.py set-status` call (story-loop 2a→2e, sprint-closure sign-off, epic/sprint promotion).
- After each write, `pm-status.py verify` — turning the manual Post-Sign-Off verification into a scripted gate.
- Graceful degradation: if the script is missing/errors, fall back to current manual-edit instructions.

Progress (pain 6): every transition also emits a `progress` line to `{sprint_root_dir}/progress.log` (user-visible, survives compaction). Intra-phase markers: dev/QA/fix subagent prompts append `PROGRESS: <task> (<n>/<m>)` after each completed task/subtask/test file.

## Phase B — Parallelism auto-mode (pain 3)

Depends on Phase A (atomic writes make concurrency safe).

Config (both PM skills):
```toml
parallel_mode          = "auto"   # "auto" | "adaptive" | "off"
max_parallel_subagents = 4        # was 2
parallel_ceiling       = 12       # NEW — hard ceiling (was hardcoded 4)
```

Logic: in `auto` mode, `effective = min(max_parallel_subagents, parallel_ceiling, safe_batch_size)` where `safe_batch_size` (already computed from dependency graph + file-overlap + no-concurrent-status-write) governs. Removes the artificial `4`.

## Phase C — Metrics hardening (pain 4, both runtimes)

Three failure modes in nested `epic → sprint → dev`: discovery depth (glob may miss 2-level nesting), session-id propagation (falls to lossy cwd fallback), transcript flush timing.

Fixes (edit `metrics-contract.md`, mirror both copies):
- Primary path: subagent self-report — each work-performing subagent runs capture scoped to its start ts and appends `tokens_k=<n|N/A> cost=<$X.XX|N/A>` to its DONE line; orchestrator sums from status lines. Transcript glob becomes reconciliation.
- Harden discovery: depth-agnostic recursion + nested-session note.
- Fail-loud under Claude: missing/`N/A` `tokens_k` is a FAILURE that halts + retries capture, not a silent write (`pm-status.py verify --require-tokens`).
- Copilot: wall-clock + man-hours stay mandatory; tokens `N/A` only with a visible annotation (`# copilot: usage not exposed by platform — not a capture failure`), never a silent loss.

## Phase D — Quality gates (pains 1 & 2)

Pain 1 — Epic architecture gate: new `references/epic-arch-gate.md` inserted between Epic Planning Step 1 and the sprint loop. Spawns `l3io-arch-review` Mode B across epics/arch/prd + all story files; gates on BLOCKER/MAJOR (resolve + record ADRs + patch stories before any sprint). Skip-with-warning if `l3io-arch-review` absent. Config: `epic_arch_gate = true`.

Pain 2 — Story technical-AC gate: (a) extend `assets/customize-architect.md` to overlay `bmad-create-story` with `standards-core` checklist; (b) new sub-step in story-loop 2a — validation subagent verifies/enriches technical ACs before `ready-for-dev`. Config: `story_technical_ac_gate = true`.
